# v0.3.24 macOS 通知授权修复与发布

## 状态

- 代码、公开 Release、macOS 包内二进制、Linux/Windows runner 安装与静态检查已完成。
- 本机 macOS 安装版尚未从 0.3.23 升级：当前前台应用为 `loginwindow`，鼠标和键盘事件无法到达 EduPi；系统通知授权弹窗也需要用户确认。因此“授权弹窗显示、通知中心显示、点击回到提醒”仍为未验收。

## 根因与修复

- v0.3.23 的 macOS 提醒使用 `mac-notification-sys` 旧 NSUserNotification 路径，发送前没有通过 UserNotifications framework 请求授权；本机 `com.apple.ncprefs.plist` 没有 EduPi 记录，原进程只留下 `edupi-notification` 等待线程。
- v0.3.24 在 `send_reminder_notification` 返回前于 Tauri 主线程请求 Alert + Sound 授权；15 秒无结果、拒绝或无法请求时返回有限错误。
- 前端把 `notification_permission_denied` 映射为“通知权限未开启，请在系统设置中允许 EduPi 通知”，超时/不可用映射为可重试提示，不向老师暴露内部 code。

## 待用户桌面会话恢复后验收

1. 从 0.3.23 应用内更新到 0.3.24，确认唯一安装副本、Core/数据/模型保持。
2. 打开设置 → 桌面端 → 测试通知跳转。
3. 在 macOS 授权弹窗选择允许；确认 `com.apple.ncprefs.plist` 出现 EduPi。
4. 确认系统通知显示，点击后 EduPi 回到提醒入口，等待线程退出。
5. 若拒绝授权，设置页应显示“通知权限未开启，请在系统设置中允许 EduPi 通知”，提醒仍留在应用内。
