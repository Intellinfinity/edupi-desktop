## 实测通知边界

- 安装包二进制包含 `UNUserNotificationCenter`、`requestAuthorizationWithOptions:completionHandler:`、`addNotificationRequest:withCompletionHandler:` 和 `EduPiNotificationDelegate`，确认修复进入公开包。
- 设置页点击“测试通知跳转”后显示“已请求发送”；原生命令返回，`edupi-notification` 等待线程不再存在，符合 UN 异步交付形态。
- 但 `com.apple.ncprefs.plist` 与系统设置通知列表均未出现 EduPi；打开通知中心后也没有 EduPi 条目。因此通知显示与点击回调不能验收通过。
- v0.3.25 的按钮只等待命令返回，未等待 `addNotificationRequest` completion，无法区分系统接受与静默失败。这是 v0.3.26 修复点。

## v0.3.26 修复方向

- 读取 UN authorization / Notification Center / alert / sound / alertStyle 五项真实状态并在设置页显示。
- macOS 发送等待系统 add request completion 后才返回；失败映射为教师可处理提示。
- 下一轮安装版验收以状态回读 + 通知中心显示 + 默认点击回到提醒为通过条件。
