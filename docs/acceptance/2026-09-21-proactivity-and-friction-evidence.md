# 主动性与无感度证据合同

## 目的

Desktop 只记录交付和交互事实，不把通知送达、点击或打开事项当成教师接受。Core 的目标、来源、审核和真人价值仍是唯一事实来源。

## 原始事件

- `candidate_created`：Desktop 首次看到一个 Core 投影的待处理候选。
- `notification_claimed`：一个候选被通知发送器领取；同一候选的重复领取会单独计数。
- `notification_delivered`：原生通知命令被系统接受。
- `notification_failed`：原生通知失败或权限/系统拒绝；自动重试最多三次，退避为 5、10、20 分钟，之后只保留应用内收件箱。
- `notification_opened`：教师点击系统通知，或打开聚合通知对应的收件箱。
- `read`、`handled`、`snoozed`：教师在应用内对提醒做出的操作。
- `candidate_withdrawn`：Core 投影不再包含原候选；Desktop 不再通知它。

## 可计算指标

`GET /api/edupi/reminders` 返回有界 `metrics`，包括候选数、待处理/稍后/已处理数、claim/送达/失败/打开数、重复 claim 数、教师操作数、送达延迟和打开延迟。指标用于验收和试用采样，不自称 precision、recall 或价值。

主动性由 Core 教师反馈中的机会分子/分母判断；Desktop 补充回答系统是否及时交付、是否重复打扰、点击是否回到对应对象以及失败后是否仍可在收件箱处理。

## 无感边界

- 窗口有焦点时不发送系统通知，当前事项仍在应用内可见。
- 同一候选只允许一个未完成通知 claim；点击后标记已读，不重复打扰。
- 通知失败自动退避并封顶，不能形成每轮轮询一次的打扰循环。
- 所有失败、撤回和点击都有事件记录；通知不可用时收件箱仍是后备入口。
- Desktop 不自动接受 Goal、Fact、学生判断或外发动作。

本合同不替代已安装 macOS/Windows、真实睡眠唤醒、系统通知中心显示和教师连续试用；这些仍需实机证据。
