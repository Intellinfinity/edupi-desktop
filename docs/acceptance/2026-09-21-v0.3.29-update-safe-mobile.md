## Safe Mode

- 以 `/Applications/EduPi.app/Contents/MacOS/pi-agent-desktop --safe-mode` 冷启动，`/api/desktop/runtime` 回读 `safeMode=true`；原生窗口显示“安全模式 / 第三方扩展已暂停 / 恢复正常启动 / 查看诊断”。教师上下文、Today 投影和基础协作界面仍可读取。
- 无参数重新启动后 `/api/desktop/runtime` 回读 `safeMode=false`，版本仍为 0.3.29。Orca 能读取恢复按钮，但一次点击因 macOS AX 临时拒绝未确认；本轮用等价的退出后无参数启动完成恢复，不把该次点击写成通过。
- 启动诊断为空，没有保存 API Key、Bearer token 或完整异常堆栈。

## 手机继续对话

- 在安装版设置中点击“启用手机入口”，应用实际重启；偏好为 `mobileBridgeEnabled=true`，server 从 loopback 改为 `*:38471`。LAN 地址 `192.168.31.99` 上 `/mobile` 返回 200，根页面和 `/api/sessions` 均返回 403。
- 桌面设置生成 8 位配对码；LAN 客户端以“安装验收手机”请求连接，桌面出现“批准”。批准后客户端收到 `active` 和 `mobile:read/mobile:chat`，token 只进入 HttpOnly、SameSite cookie，不出现在 JSON 或 localStorage。
- 已配对客户端经 LAN 回读 100 段会话和 20 条提醒；桌面设置显示“安装验收手机 · 已连接 / 撤销”。撤销后同一 cookie 请求立即返回 401。
- 验收结束将手机入口恢复为关闭并正常重启；server 重新只监听 `127.0.0.1:38471`，LAN `/mobile` 不可达。教师数据与模型哈希保持不变。
- 390×844 手机连接页和原生 800×900 设置页完成像素检查：输入、按钮、配对状态和 JEV 设置没有横向溢出或互相遮挡；1440×900 原生工作台显示 v0.3.29。

## 未验证边界

- 本轮 LAN 配对使用同一 Mac 的 LAN 地址模拟手机客户端；真实第二台 iOS/Android 设备、Wi-Fi 切换、锁屏恢复和不同路由器尚未验收。
- v0.3.29 已内置新 Raw/API updater 链路，但要到存在 v0.3.30 时才能完成“新客户端检查 → 下载 → Tauri 验签 → 原位安装”的下一跳实测。本次完成的是旧 v0.3.28 的一次手动 bootstrap。
- Windows/Linux 有本次 workflow 的干净构建和 Rust 测试证据，没有真实设备上的应用内升级证据。Apple Developer ID、公证和 TCC 跨版本保持仍未具备。
