## 本机 0.3.36 → 0.3.37 原位升级

- 更新前 `/Applications/EduPi.app` 为 `0.3.36`、PID `86147`，Core `860594a…`、投影与 Kernel ready；工作区为 51 名学生、240 任务、43 校历、9 课表，`externalSend=false`。已安装版更新接口返回最新 `0.3.37`、`updateAvailable=true`。先备份旧 `.app` 到本机临时目录，备份的 Info.plist 回读 `0.3.36`。
- 原生“管理中心 → 系统 → 应用更新”实际显示 0.3.36→0.3.37；点击“更新”后观察到准备和下载 3%。中途 Mac 自动锁屏，无法逐帧观察下载/验签/安装提示；随后同一路径 Info.plist 变为 `0.3.37`，旧 PID `86147` 退出、新 PID `22116` 启动，`/Applications` 仅有一份 EduPi.app。Tauri updater 的该调用路径为 `check → download → install → relaunch`，最终替换/重启有运行证据，但中途 UI 阶段不另称实测可见。
- 新安装版 `/api/edupi/status?summary=1` 回读 Core `68004b2c0294159eef4f88bcbf4a921ef6978037`、投影与 Kernel ready、合同 `1.1`、`externalSend=false`；工作区再次回读 51/240/43/9。模型、认证和设置三个文件的升级前后 SHA-256 各自相同，未在仓库公开摘要或密钥；JEV `enabled/active/keyConfigured=true`，手机桥接持久开关仍为 `true`，但 LAN 网关当前未就绪，不能称手机连接通过。更新接口变为当前/最新均 `0.3.37`、无可用更新。升级后的 `/Applications/EduPi.app` 再次通过 `codesign --verify --deep --strict`，`spctl --assess --type execute` 为 `accepted / Notarized Developer ID`。
- 在已安装 0.3.37 的教学页点击“对话补充重点”，新对话输入框保持空白、发送键禁用；“教学重点”作为单独可移除参考，展开只列当前学科年级与已有重点，没有预填固定指令。未发送真实模型消息，因此只验收签名版入口与文案，不冒充 AI 内容质量或提醒续聊全流程。
