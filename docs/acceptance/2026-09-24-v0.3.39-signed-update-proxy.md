## 结论

- v0.3.39 已公开，macOS 从已安装 v0.3.37 原位更新并重启；Linux/Windows 公网干净安装通过。此版首次包含更新代理设置及 Windows 已有配置的原子覆盖修复。Core 仍固定 `68004b2c0294159eef4f88bcbf4a921ef6978037`。

## 本机原位升级

- 升级前 `/Applications/EduPi.app` 为 v0.3.37，Core/投影/Kernel ready，51 名学生、240 个任务、43 项校历、9 项课表；`externalSend=false`。旧应用查询到 Latest `0.3.39`。先复制旧 `.app` 到 `/tmp/edupi-before-v039.LrMetb/EduPi.app`，核对 Info.plist 为 v0.3.37、主可执行文件摘要与原件一致，备份严格签名有效。
- 原生设置显示 v0.3.37→v0.3.39，依次观察到“正在准备更新”和“正在下载 63%”。未逐帧观察验签/安装文字，也未记录该次更新动作的发起者；随后同一路径 Info.plist 为 v0.3.39，旧 PID `32268` 退出、新 PID `42097` 启动，`/Applications` 仅有一份 EduPi.app。
- 新版 `/api/edupi/status?summary=1` 再次回读 Core/投影/Kernel ready、精确 Core commit、51/240/43/9 和 `externalSend=false`；模型、认证、设置及桌面 `ui-prefs.json` 四份文件的升级前后 SHA-256 各自相同，摘要未写入仓库。`codesign --verify --deep --strict` 成功，`spctl --type execute` 为 `accepted / Notarized Developer ID`；更新接口显示当前/最新均 `0.3.39`、无可用更新。
- 安装版设置已实际显示折叠“更新代理”；展开后本机 HTTP 代理输入为空，“留空使用系统网络”，JEV 仍启用且密钥已保存，手机入口保持原状态。尝试原生输入时辅助功能窗口中断，输入动作未获得回读；`updater-proxy.json` 仍不存在，未把保存/重启持久化或“恢复系统网络”记为通过。

## 未验证与边界

- 本机 macOS 系统代理规则指向 `127.0.0.1:7897`，但验收时没有监听进程；较早一次显式代理 GitHub 请求曾返回 200，不能代表现在持续可用。新版尚未把 7897 保存到原生配置；需在代理服务可用时保存、重启回读，并待下一版本实际走代理下载、验签、安装与重启。
- 本机独立从公开 Release 下载完整 DMG 因 CDN 连接过慢而中止，未做该 DMG 的本机摘要、挂载和 Gatekeeper 复核；runner 公证与已安装 `.app` 的本机 Gatekeeper 成功是分别成立的证据。Windows/Linux 旧版原位升级、通知点击、真实睡眠唤醒、真实教师内容质量和 R23 外部 Action 权威落账仍未验证或未实现。
- 旧候选的 Mac 预览临时根失败没有留下更细的 Core 根校验码；正式发布门禁已经通过，但 hosted runner 此类偶发测试根失败的环境原因尚未确认，不把取消的预览写为通过。
