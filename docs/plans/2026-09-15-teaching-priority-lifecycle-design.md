# 教学重点生命周期设计

## 问题与边界

“教学重点”页面目前混合显示两类只读依据：`subject_knowledge.json` 中按知识点汇总的掌握情况，以及事实脊柱中已确认的教学事实。老师只能进入 AI 对话描述想法，无法把自己的教学决定保存为可编辑对象，也没有停用、完成、删除或历史恢复。旧 `subject_knowledge` 扩展属于已退役的跨文件直接写入器，安装包不会加载；恢复它会重新引入第二条未经 Core 管理的写入路径。

教学重点应表达老师当前准备怎么教，事实和知识状态表达现有证据。两者在页面和备课上下文中关联，但不互相覆盖。

## 方案选择

采用独立的 Core 权威 `teaching_priorities.json`。每条重点有稳定 ID、学科、班级、主题、说明和状态，并由 Core 保存 revision、版本链和幂等回执。现有 `subject_knowledge` 与事实脊柱继续只读，作为创建和修订重点时的依据。

没有采用以下方案：

- 扩展 `subject_knowledge.json`：该结构以学科和主题作对象键，不能可靠表达两个班级的同名主题；手动重命名也会改变身份，并混淆教师决定与学生掌握证据。
- 把重点编码成 education fact：事实的值需要观察和来源证明；“下周先补移项”是教师计划，不应伪装成已观察事实。
- 只保存聊天摘要：无法提供稳定身份、并发控制、删除恢复和备课来源 revision。

## Core 合同

公开教育投影新增 `continuity.teaching_priorities`，每条只含当前值：

- `priority_id`
- `subject`
- `class_name`
- `topic`
- `note`
- `status`：`active`、`paused`、`completed`
- `revision`、`history_count`
- `created_at`、`updated_at`
- `external_send: false`

Core 新增 `teaching-priorities` 操作，支持 `create`、`update`、`restore`。创建和修改使用完整语义生成幂等请求标识；修改与恢复必须携带当前 revision。历史值只通过 `workspace-resources` 的显式按需参数读取，不进入普通快照。版本记录保存修改前后五个可编辑字段、来源、时间和请求标识；单对象与整文件均有界。

删除继续使用统一 tombstone，新增目标类型 `teaching_priority`。删除后普通投影和备课上下文都不可见，写入接口拒绝修改；恢复前重新核对稳定 ID、当前来源和 tombstone 指纹。对象本身不被物理移除，因此恢复不依赖浏览器提交旧值。

## 备课与桌面交互

`rhythm_heartbeat` 只读取 `active` 的教学重点，并按学科和班级匹配课次。重点的 ID 与 revision 进入任务证据；主题或说明变化会改变来源语义并使受影响课次重新准备，课次 ID 保持不变。暂停、完成或删除后，新计划不再使用该重点。

“教学重点”页面先显示老师维护的重点，再显示 Core 教学依据和知识状态。页面提供一个“新增重点”主动作；每条重点展开后可直接修改、切换状态、查看历史和删除。历史明确显示修改前与修改后，恢复替换五个可编辑字段并形成更高 revision。AI 协作入口把当前重点与事实依据写入现有全局草稿，保留清楚的教师输入位置；实际写回仍通过同一 Core API，不恢复已退役的 Agent 直写扩展。

所有成功响应都重新读取 Core 快照并核对 ID、revision、当前值和最新版本。过期页面、跨对象版本、同请求改意图、响应丢失重放、删除后重放与同名跨班重点均失败关闭或对账到已完成的同一次操作。

## 验收

隔离 Core 流程完成创建、修改、暂停、恢复、完成、删除、恢复 tombstone、重启重读和幂等重放；验证同学科同主题不同班级不串对象。修改重点后同一课次 ID 保持、来源 fingerprint 变化，暂停或删除后重点从后续备课摘要消失。

实际桌面页面完成新增、取消、保存、修改、状态变化、历史查看、历史恢复、删除、全局已删除恢复和刷新重读。教学首页、教学重点、Today/工作区中的受影响备课任务读取同一 Core 状态。源码验证包括 Core 与 Desktop 全量测试、类型、lint、安全审计和独立 P1/P2 审查；安装版证据随下一发布记录，不能由开发版替代。
